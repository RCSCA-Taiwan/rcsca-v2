# 全站架構與交付順序

更新：2026-10-19（台灣）。依協會最新決定，先完成網站架構及主要流程，名冊、文案、素材和細部規則後補。正式名冊暫不上傳，不阻擋架構工作。

## 主要世界與流程

| 區域 | 主要入口 | 流程骨架 |
| --- | --- | --- |
| 品牌與公開資訊 | `/`、`/about`、`/cycle-of-goodness` | 開場 → 認識理念 → 選擇個人、企業、關懷或連結 |
| 個人與會籍 | `/account`、`/my-1percent`、`/membership/apply` | 註冊驗證 → 入會／續會或歷史認領 → 審核 → 身分、年資、積分與紀錄 |
| 關懷與活動 | `/care-actions` | 活動／需求 → 登記或提出需求 → 核實與處理 → 本人進度及授權公開成果 |
| 企業與 ESG | `/1percent-partner` | 合作申請 → 供應或專案需求 → 審核 → 履約 → 共享成果 |
| 專業與人才 | `/1percent-network`、`/member-network` | 公開專業目錄 → 提出需求／工作／人才 → 意願回應 → 同意媒合與進度 |
| 共享所與交流 | `/share-market`、`/community` | 方案／討論 → 權限確認 → 兌換履約或內容審核 → 紀錄、取消或檢舉 |
| 管理營運 | `/admin/queue`、`/admin/operations` | 查看待辦 → 六類工作區 → 角色允許的處理 → 通知與稽核 |

`/guide` 是跨區功能入口；`/admin/operations#workspaces` 是完整後台總覽。現有 `/admin` 仍導向待辦頁。子頁的「目前位置」連回對應區域，管理員中心連回完整總覽。

功能指南支援分類與搜尋直達連結：`/guide?category=account`（個人）、`/guide?category=partner`（企業）、`/guide?category=actions`（活動）、`/guide?category=connect`（專業與人才）。`q` 可帶入搜尋詞，例如 `/guide?category=connect&q=人才`。畫面篩選同步更新網址但不堆疊每次輸入的瀏覽紀錄，重整或從功能頁返回可保留原入口；未知分類顯示全部功能。連結仍遵守各功能原有的登入及權限檢查。

## 本批架構補齊

- 補齊活動參與、需求、公開成果、生活服務、工作、人才、媒合進度及規則等功能指南入口。
- 後台依會員、關懷、企業與媒合、共享所與貢獻、交流與小隊、權限與營運整理；保留所有既有操作路徑。
- 待辦頁上方直接連至完整工作區、稽核紀錄與功能指南。
- 共用頁面名稱，補齊所有現有靜態頁及三類動態頁的位置導覽。
- 更新資料準備頁，避免仍把已實作的企業供應、履約與交流功能標示為尚未建置。

## 後續階段

申請後的銜接：`/account/requests` 除需求清單外，提供十個既有流程的追蹤／補件／結果入口，涵蓋會籍與認領、企業註冊與案件、媒合、活動核實、兌換、資料異動、通知及已核實足跡。這些入口不依賴需求清單讀取成功，也不代表每個狀態都可以修改。關懷需求及生活媒合表單直接連回此頁；未登入時保留登入後的目的地。

通知後的銜接：`/account/notifications` 依通知所屬流程連至實際申請、補件、供應、媒合、會籍或成果頁，企業補件不再導回介紹頁。履約通知沿用的事件類型無法區分兌換人與供應方，因此明列個人紀錄及需供應權限的履約工作台，不以信件文案猜測身分。讀取失敗可重試，已讀更新失敗保留原狀並提示；所有目的地仍執行原有權限檢查。

身份與驗證銜接：`/account/identity` 可前往入會／續會、歷年認領、身份驗證與通知。會籍、身份驗證及企業資格分別讀取；其中一項失敗時保留其他已確認結果，失敗項顯示尚未確認，可重新讀取。`/account/identity/verify` 讀取失敗時先提供重試，送出失敗保留輸入，送出成功與後續進度讀取失敗分別顯示，並保留返回身份頁及通知入口。

企業工作區銜接：註冊／補件、合作總覽、每期供應、預約／配送履約、提出合作需求、需求進度、企業成員與影響力成果共用工作導覽，標示目前位置，支援四種語言與手機換行。導覽不依賴各頁資料讀取，也不賦予額外權限；預先載入停用，避免只是打開導覽就讀取其他七個工作區。

歷年會員認領銜接：`/membership/claim` 從本人會籍紀錄讀回認領進度與審核備註，重新整理仍顯示待審／核准／未通過。待審與已核准時顯示結果；未通過可核對後重新送出。讀取失敗先提供重試；送出失敗保留輸入，成功後清除電話與識別碼。頁面可前往會籍、年資與生日、入會續會、通知及個人中心。這些入口不依賴認領資料讀取成功。

入會／續會銜接：`/membership/apply` 將申請進度與審核備註放在表單前方。申請紀錄與填表所需的會籍／生日資料分別判斷；表單資料讀取失敗時仍保留已確認的申請紀錄，紀錄本身失敗則不顯示空清單。重新讀取保留尚未送出的輸入，送出成功後重新確認最新進度；成功提示與後續讀取錯誤分別顯示。會籍、身份權限、通知、歷年認領與名冊入口保持可用。

個人資料銜接：`/account/profile` 的基本資料與會籍／生日分別讀取、重試；讀取失敗或資料不完整時不顯示空白編輯表單。重新讀取保留未送出的輸入，儲存失敗保留輸入，成功儲存後的讀取失敗另行提示。儲存期間禁止重複操作，生日清除時同時取消生日祝賀同意。頁面可返回入會續會、歷年認領、通知、資料異動申請及個人中心；基本資料與新增入口支援四種語言。

資料異動銜接：`/account/data-requests` 將審核進度與回覆移至表單前方，提供一般重新讀取。讀取失敗或回應不完整時不顯示空紀錄，也不允許送出；重試保留草稿。送出／撤回的成功提示與後續讀取失敗分別保留，失敗不清除輸入；補件遇到已更新的審核狀態時停止編輯，要求先查看最新進度。重置與刪除維持兩次各自勾選確認，操作期間禁止重複送出或撤回。可返回個人資料、通知、安全設定與個人中心；本頁仍只提交審核申請，不執行清除。

活動參與銜接：登記頁、核實頁與個人活動紀錄共用四語操作入口。本人登記與已核實足跡分別讀取，其中一項失敗仍保留另一項已確認的結果，不把讀取失敗當成空紀錄或零足跡。核實頁可重新讀取；個人頁顯示全部登記，取消僅限本人待核實紀錄，操作期間防止重複送出，取消成功與後續讀取失敗分別顯示。管理員核實清單明確以參與者的關聯取得資料，避免與核實人關聯混淆造成讀取失敗。核實後才建立足跡，既有角色與核實規則不變。

兌換與履約銜接：`/account/redemptions` 分別確認兌換碼、取消申請及預約／配送讀取結果，一區失敗仍可查看其他已確認結果，失敗不顯示假空紀錄。三區皆可主動重試，未送出的取消原因、問題說明或物流資料保留；成功結果與後續讀取失敗分開顯示。操作前重新驗證帳號，操作期間防止重複送出並停用編輯。重新讀取取消進度時同步更新兌換碼與履約狀態，核准取消後不再顯示舊兌換碼。提供共享所、本人兌換、通知及個人中心入口；既有審核、扣點、退點及原效期規則不變。

關懷需求詳情銜接：`/account/requests/support/[id]` 重新驗證登入並限定本人案件；案件與本人可見歷程分別讀取，一項失敗不冒充不存在或空歷程。可主動重新讀取且保留回覆草稿，送出期間禁止重複送出與編輯；成功提示與後續讀取失敗分開顯示。結案後維持唯讀，讀取失敗或不完整的案件不提供回覆表單。可回需求進度、通知與新需求入口，沿用既有承辦、補件及結案規則。

1. 架構及操作銜接：以現有路由、角色、申請／審核／結果／回到入口的流程為驗收對象。
2. 資料及內容補齊：會員名冊、活動、企業供應、案例、圖片、介紹來源及公開同意，依需要逐批提供。
3. 正式營運驗收：正式備份與異地保存、實機操作、核定積分／貢獻規則及必要帳務設定。

目前已存在註冊、會籍、活動、企業、媒合、兌換履約、交流、通知與後台的實作。入口完整不能代替真實資料或正式營運驗收。未核定的回饋比例、徽章門檻及第三方定期扣款不自行開通；空資料保持真實空狀態。
