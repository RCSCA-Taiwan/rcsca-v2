V1 驗收條件

身份不能串錯

同一人重新登入仍回到同一共享身份；重複帳號有合併流程。

點數不能憑空變動

任何共享點／XP 變動都能追到來源與操作者。

權限不能靠前端隱藏

即使直接呼叫資料 API，未授權角色仍取不到敏感資料。

金額不進 Level

同一活動不同認購金額，不產生不同共享等級。

個案不外洩

PASS IT ON 私密資料不出現在會員卡、小隊、企業端或公開 API。

歷史不能消失

既有會員加入日期與舊活動可正確帶入，不從網站上線日重新起算。

BUILD GATE

真正寫正式系統前，還有一個必要關卡。

下一步不是繼續加功能，而是把「既有資料匯入格式」定清楚：目前協會手上的會員名單、一般／永久會籍、加入日期、電話、介紹人、企業資料、歷史活動紀錄各自有哪些欄位。這會直接決定 migration schema，否則正式資料庫建完後很容易再改一次。
