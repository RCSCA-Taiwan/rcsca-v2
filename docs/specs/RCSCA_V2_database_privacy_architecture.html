敏感資料分類

資料敏感程度建議處理誰可看前台顯示
身分證字號／居留證號高度敏感第三方驗證後只留 token / hash，盡量不留原值極少數授權角色不顯示
手機／Email中度敏感加密儲存、遮罩顯示會員管理／本人依本人設定
捐款／認購金額中度敏感財務系統保存，與共享價值分離財務授權人員不顯示
PASS IT ON 個案完整敘述高度敏感加密＋個案角色控管＋查閱紀錄指定個案人員只顯示匿名摘要
特殊保護個案影像高度敏感獨立素材區，不進一般會員媒體庫極少數授權人員不公開
共享足跡／Level一般依會員公開設定本人／允許範圍可顯示
企業公開共享紀錄一般經企業與 RCSCA 審核後公開公開可顯示

正式開發時的幾條硬規則

1｜不用一張 users 表塞全部東西帳號、會籍、角色、企業管理權、點數、個案權限分開。
2｜點數一定是流水帳，不是直接改餘額每次增加、扣除、調整都有 transaction；錯了用更正紀錄，不做無痕覆寫。
3｜Level 由 XP 計算，但高階還要成就條件避免靠簽到或生活分享刷到最高「共享守護者」。
4｜介紹人與小隊分開介紹來源是歷史事實；小隊是可變更的社群歸屬。
5｜企業標章每年一筆，不覆蓋前一年2027、2028 各自留歷史，才有公信力與稽核能力。
6｜所有敏感讀取也要留紀錄不只「誰修改」，連誰查閱高敏感個案都應可追蹤。

容量先預留，不先綁死

文字與結構化資料進主資料庫；照片／影片未來走獨立媒體儲存。現在先在資料表只留 media_id、URL、權限、類型、擁有者與保存政策，避免未來因大量上傳重做核心資料庫。

容量與媒體政策暫不定案：等後續討論會員上傳量、企業 ESG 素材、影片限制與保存年限後，再決定物件儲存與 CDN。
